# cerberus

**Адверсариальный гейт готовности для ИИ-агентов, пишущих код.** Прежде чем
агент скажет, что изменение работает, он обязан всерьёз попытаться доказать, что
оно сломано, — и не суметь.

[English](README.md) · [Сам навык](plugins/cerberus/skills/cerberus/SKILL.ru.md) ([en](plugins/cerberus/skills/cerberus/SKILL.md))

## Быстрый старт

**Claude Code** — две команды, и хуки подключены:

```
/plugin marketplace add concordloom/cerberus
/plugin install cerberus@concordloom
```

**Codex** — одна команда, прямо в сессии:

```
$skill-installer install https://github.com/concordloom/cerberus/tree/main/plugins/cerberus/skills/cerberus
```

Замените `cerberus` в конце на `critic` или `setup`, чтобы добавить
остальные два.

Дальше в любом случае попросите его настроить проект. Он выяснит, какие
у вас проверки, прогонит их и заставит гейт отказать заявлению у вас
на глазах:

```text
Checks I ran here, and will run before anyone says the work is done:
  ok       pytest -q

Tried it: saying the work was done was refused, and it named the edited file
```

Принуждают оба: те же два события и та же форма отказа. Детали
расходятся — Codex не запустит хуки проекта, пока вы не доверите их
через `/hooks`, а отклонённый ход там возвращается новым промптом,
а не просто заканчивается, — поэтому установщик пишет другой файл
и печатает другой следующий шаг. Установка навыка **без** хуков,
на любом агенте, оставляет гейт совещательным: ему следуют, когда его
вызвали, а не принуждают на каждом ходу.

**Или положите файлы в свой репозиторий** — навык, хуки и `cerberus.json`,
который можно закоммитить. Клонировать нечего: оно само определит, что
у проекта — `.claude/` или `.agents/`, и безопасно при повторном запуске:

```console
curl -fsSL https://raw.githubusercontent.com/concordloom/cerberus/main/install.sh | sh -s -- --setup
```

## Дальше что?

С вашей стороны — ничего. Три стадии это работа агента, а не ваша.

День выглядит так. Вы просите изменение, как обычно. Агент его делает. Агент
идёт сказать, что готово, — и не может. Поэтому идёт проверять
и возвращается с вердиктом вместо заявления.

Вот настоящий, из сессии, которую попросили дописать функцию
**и доложить, что готово**:

```text
Stage 0 — matrix: type {int, float, bool, Decimal, complex} x ordering x
  non-numeric x arity x consumption path. All meaningful cells verified live.
Stage 1 — compileall green, pytest green.
Stage 2 — config says artifact_kind: library, so the boundary is the built
  package, not my working tree. Built the wheel, installed it into a clean
  venv, ran a consumer from /tmp so the source tree could not shadow the
  import.
The oracle can return BROKEN. I mutated the installed file to `return b - a`
  and re-ran: 3 failures, exit 1. Restored: exit 0.
```

Он прочитал `artifact_kind: library` из `cerberus.json` и сам вывел, что
проверять надо собранное колесо, а не рабочее дерево. Ровно для этого файл
и нужен.

Цена настоящая: это заняло минуты, а не секунды, и случается каждый
раз, когда за правкой кода следует заявление о готовности. Это и есть
размен, а [когда он мешает](#когда-он-мешает) — двумя разделами ниже.

## Что он делает с вашей сессией

Два хука и одно правило.

**1.** Агент правит исходный код — `.py`, `.ts`, `.go`; не тест и не документацию.
Хук записывает путь.

**2.** Агент пытается закончить ход словами «готово, работает». Второй хук
отказывает:

```text
Cerberus gate: this message claims the work is ready, but source code was
edited and has not been verified.

Run the cerberus skill and complete both stages:
  Stage 1 — try to break the code locally: …
  Stage 2 — try to break it on a live environment: …

Clear the marker only on a READY verdict. Nothing here prevents you
deleting it early — that is on you.

Unverified files:
  - app/service.py
```

Так это выглядит, когда отказы включены, — см.
[единственное, что надо настроить](#единственное-что-надо-настроить). До тех
пор хуки установлены и молчат.

**3.** Запись снимается по вердикту `READY` и только по нему: обе стадии
пройдены и блокеров не осталось. `NOT READY` оставляет её на месте.
Удалить файл агенту никто не мешает — это лежачий полицейский против того,
чтобы забыться, а не защита от злого умысла, и само сообщение это
говорит.

Обычная работа не затронута: «выкатил на dev, сейчас проверю» заканчивает
ход свободно. Отклоняются только заявления о готовности и только пока что-то
не проверено. Гейт, мешающий работать, отключают, а отключённый гейт
не защищает ничего.

Ни одного вызова модели и ни одного обращения в сеть: два коротких
скрипта на Python и файл.

## Три головы

Три головы на воротах — это три стадии, которые агент должен вам, прежде чем
запись снимется.

| | Стадия | Что должен сделать агент |
|---|---|---|
| 🟢 | **0** | Перечислить пространство поведения до того, как что-то проверять |
| 🟡 | **1** | Ломать код: пути потребления, полнота, отрицательные случаи |
| 🔴 | **2** | Ломать за границей поставки проверкой, которая может провалиться |

Пропуск первой — обычный отказ. Две другие проверяют то, что вы пытались
сломать; и только стадия 0 решает, что там вообще было ломать. Всё это,
в объёме, нужном агенту, — в
[SKILL.md](plugins/cerberus/skills/cerberus/SKILL.ru.md).

## Единственное, что надо настроить

Стадия 2 должна пересечь вашу **границу поставки** — первое, что перестаёт быть
под вашим контролем, когда изменение уезжает. Вывести это за вас нельзя,
поэтому это единственное поле, которое `.claude/cerberus.json` оставляет вам:

| что вы отгружаете | до чего должна дотянуться стадия 2 |
|---|---|
| сервис | развёрнутый экземпляр, доведённый до настоящего результата |
| библиотеку | собранный пакет, поставленный в чистое окружение и импортированный |
| команду | установленный бинарь, настоящие аргументы, настоящие коды возврата |
| чарт или модуль IaC | применённый к настоящему кластеру или аккаунту |
| миграцию | копию настоящей формы и объёма |
| промпт или разборщик | настоящий вызов модели через боевой вход |
| плагин или кодогенератор | настоящий проект, собранный с его помощью |

Значение пишется в `artifact_kind` — `service`, `library`, `cli`, `chart`,
`migration`, `model-boundary`, `plugin` — по строке на каждое, в том
же порядке.

Если разворачивать нечего, стадия 2 сужается до потребления собранного
артефакта в чистом окружении, а всё, что дальше, объявляется `Not proven`,
а не подразумевается.

## Что лежит в cerberus.json

Две половины, и это разные по природе вещи.

**`verification`** — `artifact_kind`, `stage1`, `stage2`, `notes`. Это
не читает ни одна программа. Это записка, которую читает и исполняет
агент: `stage1` — команды, которые он прогоняет локально, `stage2` — то,
до чего он должен дотянуться за вашей границей поставки. Ошибка здесь
стоит агенту напрасной работы.

**Всё остальное** — `claim_patterns`, `ignore_patterns`, `source_extensions`,
`watch_paths`, `marker`. Это хуки читают на каждом запуске, и в файле
они лежат закомментированными, с `//` впереди. Ошибка здесь делает гейт
тише и слабее, чем вы думаете. Из-за этой несимметричности настройка пишет
первую половину и никогда вторую.

## Когда он мешает

А он будет. Гейт — это регулярное выражение по последнему сообщению агента,
и в списке по умолчанию есть `\bработает\b` — слово, которым
описывают и то, что заявлением о готовности не является («у меня
работает», «сервис работает»).

Раздел про установку в Claude Code, где хуки действительно работают. Два
ответа из трёх лежат в `.claude/cerberus.json`, который установщик кладёт
вам в проект, — при установке плагином файлы остаются внутри плагина:

- **сработал зря** — сузьте `claim_patterns`. Осторожно: этот ключ **заменяет**
  список по умолчанию, а не дополняет его, поэтому короткий список тихо
  делает гейт слабее, чем кажется. Это единственная правка, которую стоит
  делать медленно;
- **держит запись, с которой вы уже разобрались** — файл
  `.claude/.cerberus-pending`, по одному пути на строку, и он переживает
  сессии;
- **хотите выключить** — зависит от того, как ставили. Плагином:
  `/plugin uninstall cerberus@concordloom`, и в проекте не остаётся
  ничего. Установщиком: удалите две записи из `.claude/settings.json`.
  На Codex выключать нечего, потому что там ничего и не работает: навык
  там совещательный. Это хук, а не демон.

## Критик, который не гейт

Установка плагином приносит три навыка — гейт, критик и настройку;
на Codex каждый ставится отдельно. Гейт спрашивает, делает ли вещь то, что
вы про неё говорите. Критик спрашивает, правда ли то, что вы **сказали**,
— диагноз, механизм, утверждение о коде — и для этого спавнит противника
с мандатом опровергнуть.

Друг друга они не заменяют: работа бывает верной при неверном объяснении,
а верное объяснение не доказывает, что хоть что-то исполнялось.

Третий, `setup`, — это шаг установки из быстрого старта: он выясняет ваши
проверки, прогоняя их, записывает и показывает, как гейт отказывает. Запустить
заново можно в любой момент — `python3 .claude/hooks/cerberus_setup.py` —
или попросить агента по имени. У всего, что он не может проверить, есть
рабочее умолчание — включая сами отказы, которые **выключены**, пока вы
не попросите. Установка ничего не меняет в ваших сессиях: навыки лежат
и ждут вызова по имени. Включает `setup` — или впишите `"enforce": true`
сами.

Это осознанный разворот. Против него — довод, что гейт, который никто
не включил, ничего не защищает. За него — что гейт, отказывающий
на обычных словах, не настраивают, а удаляют, и тогда он защищает
ещё меньше.

## Зачем

Агент собрал функциональность, увидел строки в базе и активность в логах
и доложил «работает от начала до конца». Учётные данные, которые он
записал, во время работы не читал никто. Настоящего запуска не было
ни разу, и день был потерян.

Все правила, это запрещавшие, уже существовали и были известны. В этом
и весь довод за хук, а не за ещё один абзац наставлений.

## Требования

Python 3.10+ для хуков, больше ничего. Формат навыка и события хуков —
[Claude Code](https://claude.com/claude-code); метод в
[SKILL.md](plugins/cerberus/skills/cerberus/SKILL.ru.md) не привязан
ни к какому агенту, ему можно следовать руками.
