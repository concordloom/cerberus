# cerberus

**Адверсариальный гейт готовности для ИИ-агентов, пишущих код.** Прежде чем
агент скажет, что изменение работает, он обязан всерьёз попытаться доказать, что
оно сломано, — и не суметь.

[English](README.md) · [Сам навык](plugins/cerberus/skills/cerberus/SKILL.ru.md) ([en](plugins/cerberus/skills/cerberus/SKILL.md))

## Быстрый старт

**Claude Code** — две команды, и хуки подключены:

```
/plugin marketplace add concordloom/cerberus
/plugin install cerberus@concordloom
```

**Codex** — одна команда, прямо в сессии:

```
$skill-installer install https://github.com/concordloom/cerberus/tree/main/plugins/cerberus/skills/cerberus
```

Замените `cerberus` в конце на `critic` или `setup`, чтобы добавить
остальные два.

Дальше в любом случае попросите его настроить проект. Он выяснит, какие
у вас проверки, прогонит их и заставит гейт отказать заявлению у вас
на глазах:

```text
Checks I ran here, and will run before anyone says the work is done:
  ok       pytest -q

Tried it: saying the work was done was refused, and it named the edited file
```

У Codex нет механизма хуков, поэтому там гейт совещательный: ему следуют,
когда навык вызван, а не принуждают на каждом ходу. В Claude Code хук
на остановку делает его механическим.

**Или положите файлы в свой репозиторий** — навык, хуки и `cerberus.json`,
который можно закоммитить. Клонировать нечего: оно само определит, что
у проекта — `.claude/` или `.agents/`, и безопасно при повторном запуске:

```console
curl -fsSL https://raw.githubusercontent.com/concordloom/cerberus/main/install.sh | sh -s -- --setup
```

## Что он делает с вашей сессией

Два хука и одно правило.

**1.** Агент правит исходный код. Хук записывает путь.

**2.** Агент пытается закончить ход словами «готово, работает». Второй хук
отказывает:

```text
Cerberus gate: this message claims the work is ready, but source code was
edited and has not been verified.

Unverified files:
  - app/service.py
```

**3.** Эта запись снимается ровно одним — вердиктом `READY`, который стоит
доказательств.

Обычная работа не затронута: «выкатил на dev, сейчас проверю» заканчивает ход
свободно. Отклоняются только заявления о готовности и только пока что-то
не проверено. Гейт, мешающий работать, отключают, а отключённый гейт
не защищает ничего.

## Три навыка

| | запрещает говорить | пока |
|---|---|---|
| **cerberus** | «работает» | серьёзная попытка сломать изменение не провалилась |
| **critic** | «причина в X» | независимый противник не попробовал это опровергнуть |
| **setup** | «установлено» | вы не увидели отказ своими глазами |

Первые два не заменяют друг друга: работа бывает верной при неверном
объяснении, а верное объяснение не доказывает, что хоть что-то исполнялось.

## Единственное, что надо настроить

`.claude/cerberus.json` объявляет вашу **границу поставки** — что должно быть
пересечено, чтобы изменение считалось проверенным. `setup` заполняет всё, что
может проверить запуском, и оставляет это поле вам, потому что за вас его
никто не выведет:

| что вы отгружаете | границу чего должна пересечь стадия 2 |
|---|---|
| сервис | развёрнутый экземпляр, доведённый до настоящего результата |
| библиотеку | собранный пакет, поставленный в чистое окружение и импортированный |
| команду | установленный бинарь, настоящие аргументы, настоящие коды возврата |
| чарт или модуль IaC | применённый к настоящему кластеру или аккаунту |

У всего остального есть рабочее умолчание. Гейт, который бездействует, пока
его не настроят, неотличим от отсутствующего.

## Три головы

Каждая голова — стадия, и цвет её глаза — эта стадия по всему проекту.

| | Стадия | |
|---|---|---|
| 🟢 | **Стадия 0** | Перечислить пространство поведения до того, как что-то проверять |
| 🟡 | **Стадия 1** | Ломать код: пути потребления, полнота, отрицательные случаи |
| 🔴 | **Стадия 2** | Ломать за границей поставки проверкой, которая может провалиться |

Пропуск первой — обычный отказ. Две другие проверяют то, что вы пытались
сломать; и только стадия 0 решает, что там вообще было ломать.

На практике это четыре вещи:

- **Перечислять до проверки.** Оси, их произведение, покрытие по каждой
  ячейке. Ошибки живут в смешанных ячейках — часть сущностей прошла, часть
  нет. Признак пропуска: *если пользователь дописывает вам тест-кейсы, вы этот
  шаг пропустили*.
- **Проследить путь потребления.** Для всего, что изменение пишет, найти всё,
  что это читает во время работы. «Эндпоинт вернул 200» — это не «рантайм
  этим пользуется».
- **Сделать проверку опровержимой.** До первого настоящего вызова записать,
  что опровергло бы починку. «В логах было тихо» не закрывает ничего,
  а пустая выборка — это пробел, а не успех.
- **Сообщать находки, а не опасения.** Находка — это воспроизведённый отказ
  с доказательством. «Это может сломаться» — не находка.

## Зачем

Агент собрал функциональность, увидел строки в базе и активность в логах
и доложил «работает от начала до конца». Учётные данные, которые он
записал, во время работы не читал никто. Настоящего запуска не было
ни разу, и день был потерян.

Все правила, это запрещавшие, уже существовали и были известны. В этом
и весь довод за хук, а не за ещё один абзац наставлений.

## Требования

Python 3.10+ для хуков, больше ничего. Формат навыка и события хуков —
[Claude Code](https://claude.com/claude-code); метод в
[SKILL.md](plugins/cerberus/skills/cerberus/SKILL.md) не привязан
ни к какому агенту, ему можно следовать руками.
