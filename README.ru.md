# cerberus

**Агент обязан попытаться сломать собственную правку, прежде чем скажет вам,
что она работает.** Три навыка, которые он читает и выполняет. Ни хука, ни
демона: они работают, когда их зовут.

[English version](README.md) · [Сам навык](plugins/cerberus/skills/cerberus/SKILL.ru.md) ([en](plugins/cerberus/skills/cerberus/SKILL.md))

## Установка

### Себе

Ставится лично вам и работает во всех проектах. В репозиторий ничего не пишет.

**Claude Code**

```
/plugin marketplace add concordloom/cerberus
/plugin install cerberus@concordloom
```

**Codex**

```
codex plugin marketplace add concordloom/cerberus
codex plugin add cerberus@concordloom
```

### В репозиторий

Копирует навыки в проект, чтобы они пришли из гита команде и сборке. Нужны
`curl` или `wget`, `tar` и `sh`. Кладёт в `.claude/skills/`, а если в проекте
уже есть каталог `.agents/` — то в `.agents/skills/`.

```console
curl -fsSL https://raw.githubusercontent.com/concordloom/cerberus/main/install.sh | sh -s -- --setup
```

Повторный запуск безопасен, и обновляются этим же способом.

## Удаление

```
/plugin uninstall cerberus@concordloom      # Claude Code
codex plugin remove cerberus@concordloom    # Codex
```

Если ставили в репозиторий: удалите `cerberus/`, `critic/` и `setup/` из
`.claude/skills/` или `.agents/skills/`, а также `cerberus.json`, если он больше
не нужен.

## Быстрый старт

**1. Настройте проект.** Скажите агенту:

```
Прогони навык setup на этом проекте.
```

Он найдёт ваши тесты и линтеры, прогонит их и запишет те, что прошли. Вывод
английский; агент перескажет его вам по-русски.

```text
Set up: Python library — change that if it is wrong.

Checks I ran here and wrote down:
  ok       pytest -q
```

**2. Дальше, прежде чем поверить, что «работает»:**

```
Прогони навык cerberus по этому изменению.
```

Работает лучше, когда есть задача, написанная **до** правки: без неё агент
выводит, что проверять, из диффа, — а это и есть тот сбой, ради которого навык
существует. Что приходит в ответ:

```text
Stage 1 — pytest 24 passed, ruff clean.
Stage 2 — built the wheel, installed it into a clean venv, ran a consumer
  from /tmp so the source tree could not shadow the import. Correct for
  0.5, negative amounts and zero.
  Old HEAD's wheel returned 12.6 for the same input and the check rejected
  it, so the check can fail.
Not proven: behaviour at exactly 0.5 — no rule was agreed.

Verdict: READY
```

`NOT READY` приходит так же — с тем, что сломалось, и как это воспроизвести.

## cerberus.json

Один файл в корне проекта, и читают его только навыки. Вот он целиком:

```json
{
  "verification": {
    "artifact_kind": "service",
    "stage1": ["pytest -q", "ruff check ."],
    "stage2": [
      "docker compose up -d --wait",
      "curl -fsS localhost:8080/orders -d @fixtures/order.json | jq -e '.status == \"accepted\"'"
    ],
    "notes": "только dev-кластер, прод не трогать. Доступы в .envrc."
  }
}
```

`setup` записывает `artifact_kind` и `stage1`, предварительно прогнав команды.
`stage2` — за вами, про него ниже. `notes` — всё, что агенту стоит знать и чего
он не прочитает с диска.

У старых установок файл лежит в `.claude/cerberus.json` или
`.codex/cerberus.json`; оба пути по-прежнему читаются.

## Три головы

Три головы над вратами — это три стадии.

| | Стадия | Что обязан сделать агент |
|---|---|---|
| 🟢 | **0** | Перечислить, что может сломаться, до того как что-то проверять |
| 🟡 | **1** | Ломать код: как им пользуются снаружи, полнота, негативные случаи |
| 🔴 | **2** | Ломать там, где оно правда работает, проверкой, которая может упасть |

Пропускают обычно стадию 0. Две другие проверяют то, что вы додумались
попробовать; только стадия 0 решает, что вообще стоило пробовать. Метод целиком,
в том объёме, который нужен агенту, — в
[SKILL.ru.md](plugins/cerberus/skills/cerberus/SKILL.ru.md).

## Стадия 2 и граница поставки

Стадия 2 обязана дотянуться за первое, что перестаёт быть под вашим контролем,
когда изменение уезжает:

| `artifact_kind` | куда обязана дотянуться стадия 2 |
|---|---|
| `service` — сервис или приложение | до развёрнутого экземпляра и настоящего результата |
| `library` — пакет | до собранного пакета в чистом окружении, импортированного как потребителем |
| `cli` — команду | до установленной команды, реальных аргументов и кодов возврата |
| `chart` — чарт или IaC-модуль | до применения к настоящему кластеру или аккаунту |
| `migration` — изменение схемы | до копии реальной структуры и объёма |
| `model-boundary` — промпт или парсер | до реального вызова модели через боевую точку входа |
| `plugin` — плагин или кодоген | до настоящего проекта, который собирают с его помощью |

**Если раскатывает CI**, стадия 2 такая: запушить, дождаться пайплайна командой,
которая падает вместе с ним, и доказать, что отвечает **именно этот** коммит —
эндпоинтом `/version` с sha или дайджестом образа на живом деплойменте. Ожидание
проверкой не является: без такой сверки вы зазеленеете против сборки, которая
там уже стояла.

Для `service` и `chart` скрипт настройки умеет набросать эти команды из ваших
`helm/`, манифестов, compose или джобы деплоя — попросите агента запустить
`setup` с ключом `--draft-stage2`. Он напечатает черновик с пропусками и назовёт
ловушки, а записывать ничего не станет. Для остальных пяти видов черновика нет,
и спецификация — таблица выше.

**Если разворачивать правда некуда**, не оставляйте `stage2` пустым — добавьте
рядом `"stage2_unreachable": "dev-кластера нет, катим руками"`. Тогда каждый
вердикт сузится до `READY scope: Stage 1` и процитирует вашу причину. А когда
`stage2` заполнен, выполнять его уже обязательно.

## Что это делает с вашей сессией

Ни хука, ни фонового процесса, ни одного вашего файла, который правился бы при
установке. Навыки — это текст, который агент читает, когда вы просите; он может
взяться за них и сам, услышав «готово», — это его суждение, и ему можно сказать
так не делать.

Что действительно выполняется: `setup` запускает у вас в проекте команды-кандидаты,
чтобы выяснить, какие проходят. Стадия 2 запускает те команды, которые **вы**
положили в `stage2`, с теми доступами, что есть у вашей оболочки, — если они
дотягиваются до настоящего кластера, напишите об этом в `notes` и направьте их
на безопасный.

Сам инструмент не вызывает модель и в рантайме ничего не тянет из сети, но
установка качает с гитхаба, а стадия 2 для вида `model-boundary` — это вызов
модели по определению. Три стадии у агента стоят токенов и занимают минуты, а не
секунды. Это и есть цена; решать, когда её платить, вам — потому и не запускается
ничего само.

## Критик — это про другое

Навыков три: `cerberus`, `critic`, `setup`. `cerberus` спрашивает, делает ли
изменение то, что вы про него говорите. `critic` спрашивает, правда ли то, что
вы *сказали*, — диагноз, механизм, утверждение о коде: он запускает второго
агента, которому поручено это опровергнуть. Один другого не покрывает: работа
может быть верной при неверном объяснении, а верное объяснение не доказывает,
что хоть что-то запускалось.

## Зачем

Агент собрал функциональность, увидел строки в базе и активность в логах и
доложил: «работает от начала до конца». Учётные данные, которые он записал, в
рантайме не читал никто. Настоящего запуска не было ни одного, и день был
потерян.

Сделать так, чтобы проверка срабатывала автоматически, пробовали и отказались:
хук умеет понять, что код изменился, и никогда — важно ли изменение, а
перебивать по неверной догадке — верный способ быть снесённым.

## Требования

Python 3.10+ для скрипта настройки. Маршруту с репозиторием нужны ещё `curl` или
`wget`, `tar` и `sh`. Формат навыка — это формат
[Claude Code](https://claude.com/claude-code) и Codex; метод из
[SKILL.ru.md](plugins/cerberus/skills/cerberus/SKILL.ru.md) не привязан ни к
какому агенту, и его можно выполнять руками.
