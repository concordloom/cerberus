# cerberus-skill

**Адверсариальный гейт готовности для ИИ-агентов, пишущих код.** Прежде чем
агент скажет, что изменение работает, он обязан всерьёз попытаться доказать, что
оно сломано, — и не суметь.

[English](README.md) · [Сам навык](plugins/cerberus/skills/cerberus/SKILL.ru.md) ([en](plugins/cerberus/skills/cerberus/SKILL.md))

## Три головы

| | что запрещает говорить |
|---|---|
| **гейт** | «работает» — пока серьёзная попытка сломать изменение не провалилась |
| **критик** | «причина в X» — пока независимый разбор не попробовал это опровергнуть |
| **настройка** | «установлено» — пока вы не увидели отказ своими глазами |

Один плагин, одна установка, три [навыка](plugins/cerberus/skills/). Первые два
не заменяют друг друга: работа бывает верной при неверном объяснении, а верное
объяснение не доказывает, что хоть что-то исполнялось.

## Проблема

Агент собирает фичу, видит строки в базе и активность в логах и отчитывается
«работает end-to-end». Учётные данные, которые он записал, в рантайме не
резолвились нигде. Реального прогона не было ни одного.

Дело не в невнимательности модели. Это структурное свойство того, как обычно
идёт проверка: автор проверяет свою же работу, по тому пути, который у него уже
в голове, и всё, на что он смотрит, с ним соглашается. Написанные инструкции это
не лечат — правила, запрещавшие каждый из этих шагов, уже существовали и были
известны.

## Что это

Четыре вещи, работающие вместе:

1. **Навык** ([SKILL.ru.md](plugins/cerberus/skills/cerberus/SKILL.ru.md)), описывающий, из чего обязана состоять
   проверка: перечислить пространство поведения до того, как его проверять;
   проследить, кто читает записанные значения; и затем попытаться сломать
   изменение за границей поставки проверкой, которая действительно способна
   вернуть `BROKEN`.
2. **Второй навык — [критик](plugins/cerberus/skills/critic/SKILL.ru.md)** — на вторую половину цикла.
   Гейт спрашивает, делает ли вещь то, что вы про неё говорите; критик — правда
   ли то, что вы **сказали**: диагноз, механизм, утверждение о кодовой базе. Для
   этого он порождает адверсария с мандатом опровергнуть. Работа бывает верной
   при неверном объяснении, а верное объяснение не доказывает, что хоть что-то
   исполнялось, — поэтому один не покрывает другого.
3. **Два хука**, делающих это механикой, а не вопросом памяти. Один фиксирует,
   что исполняемый код изменился; второй не даёт закончить ход заявлением о
   готовности, пока эта запись существует.
4. **Вердикт** — либо `READY` с доказательствами, либо `NOT READY` с
   воспроизведениями. Запись снимает только `READY`.

## Три головы

Каждая голова — стадия, и цвет её глаза означает эту стадию везде: в знаке, в
документации, в отчётах.

| | Стадия | Что делает |
|---|---|---|
| 🟢 | **Стадия 0** | Перечислить пространство поведения до того, как что-то проверять |
| 🟡 | **Стадия 1** | Ломать код: пути потребления, полнота, негатив |
| 🔴 | **Стадия 2** | Ломать за границей поставки, проверкой, способной опровергнуть |

Пропускают обычно первую. Две другие проверяют то, что ты пытался сломать, и
только Стадия 0 решает, что там вообще было ломать.

## Установка

### Claude Code — две команды

```
/plugin marketplace add concordloom/cerberus-skill
/plugin install cerberus@concordloom
```

Это всё. Навык и оба хука установлены и подключены: ничего копировать и никаких
настроек править не нужно.

### Codex — одна команда

```console
gh skill install concordloom/cerberus-skill cerberus --agent codex
```

Ничего особенного для этого не требуется: репозиторий разложен так, как ожидает
экосистема, и `gh skill` находит навык сам — «found 1 skill using the plugins/
convention», — а установку закрепляет за последним релизным тегом. Внутри самого
Codex то же самое принимает `$skill-installer`, только адресом:

```console
$skill-installer install https://github.com/concordloom/cerberus-skill/tree/main/plugins/cerberus/skills/cerberus
```

Оба пути кладут навык в `.agents/skills` — этот каталог Codex делит с Copilot,
Cursor, Gemini CLI и десятком других агентов, так что одна установка служит и им.

Ставится только навык, и для Codex это вся история: механизма хуков у него нет,
поэтому гейт там рекомендательный — выполняется при вызове, а не принуждается на
каждом ходу. В Claude Code его делает механикой Stop-хук.

### Либо положить файлы в свой репозиторий

Если хочется, чтобы всё лежало в проекте — навык, хуки и `cerberus.json`, который
можно править, — это делает установщик; заодно он подключает хуки к настройкам
там, где они есть:

```console
curl -fsSL https://raw.githubusercontent.com/concordloom/cerberus-skill/main/install.sh | sh
```

Клонировать ничего не нужно: запущенный через `sh` скрипт сам забирает то, что
ему требуется. Он определит, что использует проект — `.claude/` или `.agents/`, —
положит файлы куда надо, и его безопасно запускать повторно.

Настраивать для старта ничего не нужно: у каждого ключа есть рабочее умолчание,
потому что гейт, который бездействует, пока его не настроят, неотличим от
отсутствующего. Когда дойдут руки — опишите границу поставки своего проекта в
`.claude/cerberus.json`, чтобы Стадия 2 была фактом, а не догадкой.

## Чего он на самом деле требует

**Перечислить до того, как проверять.** Выписать оси фичи и их декартово
произведение, отметить покрытие по каждой клетке и обратить внимание на
смешанные: часть сущностей прошла, часть упала. Баги живут там. У пропуска этого
шага есть признак: *если пользователь дописывает тебе кейсы — ты его пропустил.*

**Проследить путь потребления.** Для всего, что изменение пишет, найти всё, что
это читает в рантайме. «Эндпоинт вернул 200» — это не «рантайм это использует».

**Перейти границу поставки.** Проверка на своих условиях — своё дерево, свои
фикстуры, свои импорты — не видит того, что ломается только снаружи. Граница
находится вопросом *что первое перестаёт быть под моим контролем*, и проверять
надо с её дальней стороны, над произведённым артефактом.

Для сервиса это развёрнутый экземпляр. Для библиотеки — собранный пакет,
установленный в чистое окружение и импортированный как у потребителя; именно там
живут забытый экспорт и несовместимый диапазон версий, невидимые ни одному
внутреннему тесту, потому что те импортируют из исходников.

**Сделать проверку фальсифицируемой.** До первого настоящего вызова записать,
что опровергло бы фикс: гипотезу неполноты, неблагоприятную предпосылку,
доказательство того, что этот путь действительно достигнут, и оракул отказа,
способный вернуть `BROKEN`. «В логах вроде тихо» не доказывает ничего и не
закрывает ничего. Пустая выборка — это пробел, а не успех.

**Сообщать находки, а не тревоги.** Находка — воспроизведённый сбой с
доказательством. «Может сломаться» — не находка. Гейт, который кричит «волки»,
выключают, а выключенный гейт не защищает ни от чего.

## Требования

Python 3.10+ для хуков. Больше ничего.

Формат навыка и события хуков — из [Claude
Code](https://claude.com/claude-code); сам метод в `SKILL.ru.md` ни к какому
агенту не привязан и выполним руками.

## Происхождение и лицензия

Выделено из внутренних инженерных правил платформы автоматизации на ИИ, где
появилось после описанного выше инцидента и укреплялось каждый раз, когда
обнаруживался новый способ обойти гейт. MIT — см. [LICENSE](LICENSE).
