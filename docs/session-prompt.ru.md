# Промпт для новой сессии по самому церберу

Скопировать целиком в новую сессию, запущенную **в каталоге репозитория**
`~/Work/greenlabs/cerberus`. Файл живёт в репозитории намеренно: он
переживает сессии, а память ассистента — нет.

---

Работаем над этим репозиторием — `concordloom/cerberus`. Сессия должна
быть укоренена именно здесь: хуки гейта грузятся из проекта, в котором укоренена
сессия, и при работе из чужого каталога они не сработают вовсе — гейт окажется
вне контура, а самоедство станет номинальным.

## Что это

Публичный репозиторий под MIT: адверсариальный гейт проверки для агентов,
работающих с кодом. Одновременно площадка плагинов Claude Code и источник
навыков для Codex и всех, кто читает `.agents/skills`. В одном плагине два
навыка: `cerberus` проверяет **работу**, `critic` проверяет **утверждения**.
Текущий релиз — v1.2.0, `semantic-release` выпускает на каждый push в `main`.

## Правила, которые не обсуждаются

- **Внутренности по-английски**: код, комментарии, CI, задачи и сообщения
  коммитов — из них генерируется changelog. Исключение ровно одно: переводы
  `SKILL.ru.md` и `README.ru.md`.
- **Русский текст перед фиксацией — через `ru-text`**: кавычки «ёлочки»,
  длинное тире в прозе, неразрывный пробел после `в к с о у и а`, многоточие
  одним символом. Счётчику навыка не верить: проверять каждое срабатывание
  построчно, иначе правка ломает разметку, которую он посчитал прозой.
- **Обе языковые версии меняются вместе.** `scripts/check_parity.py` сверяет
  структуру заголовков, число пунктов чеклиста и число кодовых блоков по всем
  навыкам `plugins/*/skills/*`.
- **Версия пишется в два манифеста** (`scripts/set_version.py`). Установка из
  площадки обновляется, только когда меняется строка `version`; релиз, который
  лишь поставил тег, не доезжает ни до кого.
- **Цикл работы:** `/issue` заканчивает обсуждение задачей, `/work <номер>`
  ведёт её через матрицу → работу → критика → цербера → вердикт. Матрица
  публикуется в задачу **до** работы, вердикт с доказательствами — после.
- **Перед словами «работает» или «готово» — `/cerberus` до `READY`.** Стадия 2
  проверяется за границей поставки: для этого репозитория это загрузчик
  плагинов на **запушенном** коммите и опубликованный тег через
  `gh skill install`. Рабочее дерево их не заменяет.
- **Push отвергается почти всегда** — `semantic-release` кладёт в `main` свой
  `chore(release)`. Лечится `git fetch` и `git rebase origin/main`, а не силой.

## Что уже доказано, перепроверять без нужды не надо

- `gh skill install concordloom/cerberus --all --agent codex` на v1.2.0
  находит оба навыка и ставит их в `.agents/skills`.
- `curl -fsSL …/install.sh | sh` работает без клона и ставит все навыки
  плагина; установленный гейт блокирует заявление готовности и молчит без
  отметки — обе стороны сняты.
- Страж паритета краснеет на отсутствующем переводе и на разошедшейся
  структуре; проверка формы задачи в CI краснеет, если снять обязательность
  поля-оракула.

## Что не доказано и ждёт работы

1. **Форму задачи не подтвердил сам GitHub.** Страница `issues/new/choose` за
   логином, API распарсенных шаблонов нет, `community/profile` слеп к каталогу
   `ISSUE_TEMPLATE/` — проверено контрольным `cli/cli`, у которого формы есть, а
   ответ такой же пустой. Открыть руками и убедиться, что форма отрисована и
   обязательное поле на месте.
2. **Команды `/issue` и `/work` никто не вызывал.** `claude plugin validate` их
   не проверяет: он принимает заведомо битый фронтматтер, это измерено.
   Доказательство только вызовом.
3. **Обновление установленного плагина не проверялось от начала до конца.**
   Поставить прежнюю версию в изолированный `CLAUDE_CONFIG_DIR`, выпустить
   новую, выполнить `claude plugin update` с рестартом и убедиться, что до
   установки доехала именно новая.
4. **Расхождение с внутренней копией в `ai-tsex`:** там 422 строки и 18
   заголовков, здесь 526 и 19 — внутренняя не знает ни рабочего цикла, ни
   обобщённой границы поставки. Решить осознанно: тянуть цикл внутрь или
   развести версии, записав почему.

## С чего начать

Прогнать цикл на самом себе: взять пункт 1 или 2, завести его через `/issue` и
провести через `/work`. Тогда в репозитории появится первая задача, прошедшая
полный контур, — и это единственное предъявление, что цикл живой, а не описан.
